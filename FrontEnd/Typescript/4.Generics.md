# TypeScript Generics

## Basic Generics

### Generic Functions
```typescript
// Basic generic function
function identity<T>(arg: T): T {
    return arg;
}

// Usage
let output1 = identity<string>("myString");
let output2 = identity("myString");  // Type inference
```

### Generic Interfaces
```typescript
interface GenericIdentityFn<T> {
    (arg: T): T;
}

// Implementation
let myIdentity: GenericIdentityFn<number> = identity;
```

### Generic Classes
```typescript
class GenericNumber<T> {
    zeroValue: T;
    add: (x: T, y: T) => T;
}

// Usage
let myGenericNumber = new GenericNumber<number>();
myGenericNumber.zeroValue = 0;
myGenericNumber.add = function(x, y) { return x + y; };
```

## Generic Constraints

### Using extends
```typescript
interface Lengthwise {
    length: number;
}

function loggingIdentity<T extends Lengthwise>(arg: T): T {
    console.log(arg.length);  // Now we know it has a .length property
    return arg;
}
```

### Using Type Parameters
```typescript
function getProperty<T, K extends keyof T>(obj: T, key: K) {
    return obj[key];
}

let x = { a: 1, b: 2, c: 3 };
getProperty(x, "a"); // OK
getProperty(x, "m"); // Error: Argument of type 'm' isn't assignable
```

### Class Types
```typescript
function create<T>(c: { new(): T; }): T {
    return new c();
}

// Usage with class
class BeeKeeper {
    hasMask: boolean;
}

class ZooKeeper {
    nametag: string;
}

class Animal {
    numLegs: number;
}

class Bee extends Animal {
    keeper: BeeKeeper;
}

class Lion extends Animal {
    keeper: ZooKeeper;
}

function createInstance<A extends Animal>(c: new () => A): A {
    return new c();
}
```

## Advanced Patterns

### Generic Parameter Defaults
```typescript
interface GenericInterface<T = string> {
    value: T;
    process: (input: T) => void;
}

// Default to string if no type provided
class GenericClass<T = string> implements GenericInterface<T> {
    value: T;
    process(input: T): void {
        // Implementation
    }
}
```

### Conditional Types
```typescript
type TypeName<T> =
    T extends string ? "string" :
    T extends number ? "number" :
    T extends boolean ? "boolean" :
    T extends undefined ? "undefined" :
    T extends Function ? "function" :
    "object";

// Usage
type T0 = TypeName<string>;  // "string"
type T1 = TypeName<"a">;     // "string"
type T2 = TypeName<true>;    // "boolean"
```

### Generic Type Inference
```typescript
function merge<T1, T2>(arg1: T1, arg2: T2): T1 & T2 {
    return { ...arg1, ...arg2 };
}

// Type inference in action
const result = merge(
    { name: "John" },
    { age: 30 }
);  // Type is { name: string } & { age: number }
```

### The `infer` keyword (extracting types inside conditional types)
`infer` lets you **capture** a sub-type from within a conditional type instead of just testing it. It's how many built-in utility types are implemented.

```typescript
// Extract the element type of an array
type ElementType<T> = T extends (infer U)[] ? U : T;
type A = ElementType<string[]>; // string
type B = ElementType<number>;   // number (not an array, falls through)

// This is literally how ReturnType<T> and Parameters<T> are built:
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;
type MyParameters<T> = T extends (...args: infer P) => any ? P : never;
```

### Distributive Conditional Types
When a conditional type's checked type is a **naked type parameter** and you pass in a union, TS distributes the conditional over each member of the union individually.
```typescript
type ToArray<T> = T extends any ? T[] : never;

type Result = ToArray<string | number>;
// Distributes to: string[] | number[]  (NOT (string | number)[])
```
This is why `Exclude<T, U>` and `Extract<T, U>` work member-by-member on unions rather than treating the union as one opaque type.

### Variance annotations: `in` / `out` (TS 4.7+)
For generic interfaces/types, you can explicitly declare whether a type parameter is used in an input (`in`, contravariant) or output (`out`, covariant) position. This mostly matters for library authors documenting/enforcing intent — the compiler already infers variance, but explicit annotations catch accidental misuse and improve error messages.
```typescript
interface Producer<out T> {
    make(): T;       // T only appears in output position
}
interface Consumer<in T> {
    consume(value: T): void; // T only appears in input position
}
```

## Best Practices

### 1. Use Meaningful Names
```typescript
// Good
interface Repository<TEntity> {
    findById(id: string): Promise<TEntity>;
    save(entity: TEntity): Promise<void>;
}

// Avoid
interface Repository<T> {
    findById(id: string): Promise<T>;
    save(item: T): Promise<void>;
}
```

### 2. Constrain When Necessary
```typescript
// Good - Constrained to objects with id
interface HasId {
    id: string | number;
}

function deleteEntity<T extends HasId>(entity: T): void {
    console.log(`Deleting entity with id ${entity.id}`);
}

// Avoid - Too permissive
function deleteEntity<T>(entity: T): void {
    console.log(`Deleting entity`);
}
```

### 3. Use Factory Patterns
```typescript
class GenericFactory<T> {
    create<K extends keyof T>(type: K, props: T[K]): T[K] {
        return props;
    }
}

// Usage
interface Parts {
    arm: { length: number };
    leg: { strength: number };
}

const factory = new GenericFactory<Parts>();
const arm = factory.create('arm', { length: 10 });
```

### 4. Generic Constraints with Union Types
```typescript
type StringOrNumber = string | number;

function getValue<T extends StringOrNumber>(value: T): T {
    return value;
}

// Usage
getValue("hello");  // OK
getValue(123);      // OK
getValue(true);     // Error
```

### 5. Generic Error Handling
```typescript
class Result<T, E extends Error> {
    private constructor(
        private value?: T,
        private error?: E
    ) {}

    static success<T>(value: T): Result<T, never> {
        return new Result(value);
    }

    static failure<E extends Error>(error: E): Result<never, E> {
        return new Result(undefined, error);
    }

    isSuccess(): boolean {
        return this.error === undefined;
    }

    getValue(): T {
        if (this.error) throw this.error;
        return this.value!;
    }
}

// Usage
function divide(a: number, b: number): Result<number, Error> {
    if (b === 0) {
        return Result.failure(new Error("Division by zero"));
    }
    return Result.success(a / b);
}
```

## Common Use Cases

### 1. Generic Components
```typescript
interface ListProps<T> {
    items: T[];
    renderItem: (item: T) => React.ReactNode;
}

function List<T>({ items, renderItem }: ListProps<T>) {
    return (
        <ul>
            {items.map((item, index) => (
                <li key={index}>{renderItem(item)}</li>
            ))}
        </ul>
    );
}
```

### 2. Generic HTTP Service
```typescript
class HttpService {
    async get<T>(url: string): Promise<T> {
        const response = await fetch(url);
        return response.json();
    }

    async post<T, U>(url: string, data: T): Promise<U> {
        const response = await fetch(url, {
            method: 'POST',
            body: JSON.stringify(data),
            headers: {
                'Content-Type': 'application/json'
            }
        });
        return response.json();
    }
}
```

### 3. Generic State Management
```typescript
class Store<State> {
    private state: State;
    private listeners: ((state: State) => void)[] = [];

    constructor(initialState: State) {
        this.state = initialState;
    }

    getState(): State {
        return this.state;
    }

    setState(newState: Partial<State>): void {
        this.state = { ...this.state, ...newState };
        this.notify();
    }

    subscribe(listener: (state: State) => void): () => void {
        this.listeners.push(listener);
        return () => {
            this.listeners = this.listeners.filter(l => l !== listener);
        };
    }

    private notify(): void {
        this.listeners.forEach(listener => listener(this.state));
    }
}
```

## Interview quick hits
- **Q: What problem do generics solve?** Reusing logic/components across multiple types without losing type safety (avoiding `any`).
- **Q: How do you constrain a generic type?** `<T extends SomeShape>` restricts T to types that satisfy `SomeShape`, enabling safe access to its members.
- **Q: What does `infer` do inside a conditional type?** Captures/extracts a type from a matched position instead of just testing it — the mechanism behind `ReturnType<T>`, `Parameters<T>`, `Awaited<T>`.
- **Q: What is a distributive conditional type?** A conditional type over a naked generic type parameter that, when given a union, applies itself to each union member individually rather than the whole union at once.
- **Q: `T` vs `keyof T` vs `T[K]`?** `T` is the type itself; `keyof T` is a union of its property name literals; `T[K]` (indexed access) is the type of the property at key `K`.
