# TypeScript Symbols

## What is a `symbol`?
`symbol` is a **primitive type** (like `number`, `string`, `boolean`) introduced in ES2015. Every value created by `Symbol()` is **guaranteed unique** — even two symbols created with the exact same description are never equal.

```typescript
let sym1 = Symbol("key");
let sym2 = Symbol("key");

console.log(sym1 === sym2); // false — always unique
```

## Why symbols exist (the real-world reason)
Before symbols, JavaScript objects only had string keys — which meant libraries/mixins could **accidentally collide** on property names (e.g., two mixins both adding a `.id` property). Symbols give you a **collision-proof key** for object properties.

```typescript
const id = Symbol("id");

const user = {
    name: "Alice",
    [id]: 123, // computed property key
};

console.log(user[id]); // 123
// user.id is NOT the same as user[id] — no collision risk
```

## Symbols as "hidden" keys
Symbol-keyed properties are **skipped** by `JSON.stringify`, `for...in`, and `Object.keys()` — useful for metadata that shouldn't leak into normal iteration/serialization.

```typescript
console.log(Object.keys(user));        // ["name"] — symbol key excluded
console.log(JSON.stringify(user));     // {"name":"Alice"}
```

## `unique symbol` type
A special type for `const` symbol declarations, used mainly to type-safely key into objects (common in library code / custom well-known symbols).

```typescript
declare const key: unique symbol;

interface Tagged {
    [key]: string;
}
```

## Well-known symbols (built into JS/TS)
These hook into language-level behavior:

| Symbol | Purpose |
|---|---|
| `Symbol.iterator` | Makes an object usable in `for...of`, spread `...`, destructuring |
| `Symbol.asyncIterator` | Same, but for `for await...of` |
| `Symbol.hasInstance` | Customize `instanceof` behavior |
| `Symbol.toPrimitive` | Customize how an object converts to a primitive (`+obj`, `` `${obj}` ``) |

```typescript
class Range {
    constructor(private start: number, private end: number) {}

    [Symbol.iterator]() {
        let current = this.start;
        const end = this.end;
        return {
            next(): IteratorResult<number> {
                return current < end
                    ? { value: current++, done: false }
                    : { value: undefined, done: true };
            },
        };
    }
}

for (const n of new Range(1, 4)) {
    console.log(n); // 1, 2, 3
}
```

## Interview quick hits
- **Q: Are two symbols with the same description equal?** No — uniqueness is guaranteed regardless of description.
- **Q: Can symbol-keyed properties be accessed via dot notation?** No — only via bracket notation `obj[sym]`.
- **Q: Why use a symbol instead of a string key?** To guarantee no property name collisions (library/mixin safety) and to implement protocol hooks like `Symbol.iterator`.
