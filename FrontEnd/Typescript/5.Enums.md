## Enums

>>Enums allow us to define a set of named constants.

### Numeric enums
    enum Direction {
        Up = 1,
        Down,
        Left,
        Right,
    }
Up is initialized with 1. All of the following members are auto-incremented from that point on. In other words, Direction.Up has the value 1, Down has 2, Left has 3, and Right has 4.

    enum Direction {
        Up,
        Down,
        Left,
        Right,
    }
Up would have the value 0, Down would have 1, etc. This auto-incrementing behavior is useful for cases where we might not care about the member values themselves,

### String enums
While string enums don’t have auto-incrementing behavior

    enum Direction {
        Up = "UP",
        Down = "DOWN",
        Left = "LEFT",
        Right = "RIGHT",
    }

### Heterogeneous enums
Technically enums can be mixed with string and numeric members, but it's not clear why you would ever want to do so:

    enum BooleanLikeHeterogeneousEnum {
        No = 0,
        Yes = "YES",
    }

## const enum

    const enum Enum {
        A = 1,
        B = A * 2,
    }

`const enum` is fully inlined at compile time — no object is generated in the emitted JS, giving zero runtime overhead. Trade-off: it cannot be used with `isolatedModules: true` (common in Babel/esbuild/SWC-based toolchains, Vite, ts-jest with isolated compilation) because those tools compile files independently and can't resolve the enum's values across files.

## Senior recommendation: enum vs union literal type
In modern TypeScript codebases (React/Node), many senior engineers prefer string literal union types over enums:

```typescript
type Direction = "Up" | "Down" | "Left" | "Right";
```

| | `enum` | Union of literals |
|---|---|---|
| Runtime cost | Generates a JS object (unless `const enum`) | Zero — erased entirely at compile time |
| Works with `isolatedModules` | `const enum` breaks it | Always works |
| Extensibility | Closed set, needs enum member | Just add a string to the union |
| Interop with plain JS/JSON | Awkward (needs `as Direction`) | Natural — it's just a string |

> Use `enum` when you need reverse mapping or a namespace-like grouping of related constants; use a union of string literals for most "one of these values" cases — simpler, safer with modern build tools, and zero runtime footprint.

## Reverse mapping (numeric enums only)
Numeric enums generate a two-way map at runtime — name → value and value → name:

```typescript
enum Direction2 { Up = 1, Down, Left, Right }
console.log(Direction2.Up); // 1
console.log(Direction2[1]); // "Up"
```

This reverse mapping is **not** generated for string enums.

## Interview quick hits
- **Q: What's the runtime representation of a numeric enum?** A JS object with both forward (name→value) and reverse (value→name) mappings.
- **Q: Does a string enum have reverse mapping?** No.
- **Q: Why avoid `const enum` in some build setups?** It's incompatible with `isolatedModules` (single-file transpilation used by Babel/esbuild/SWC).
- **Q: When would you choose a union type over an enum?** When you want zero runtime cost, simpler interop with plain strings/JSON, and don't need reverse mapping.
