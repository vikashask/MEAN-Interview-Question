# Iterators and Generators

## Iterables
An object is **iterable** if it implements `Symbol.iterator`. Many built-in types are already iterable: `Array`, `Map`, `Set`, `String`, `Int32Array`, `Uint32Array`, etc.

## `for...of` statement
`for...of` loops over the **values** produced by an iterable:
```typescript
let someArray = [1, "string", false];

for (let entry of someArray) {
    console.log(entry); // 1, "string", false
}
```

## `for...of` vs `for...in`
| | Iterates over | Example output for `[4, 5, 6]` |
|---|---|---|
| `for...in` | **Keys** (indices as strings, or object property names) | `"0", "1", "2"` |
| `for...of` | **Values** | `4, 5, 6` |

```typescript
let list = [4, 5, 6];

for (let i in list)  console.log(i); // "0", "1", "2"
for (let i of list)  console.log(i); // 4, 5, 6
```
> Pitfall: don't use `for...in` on arrays when you want values — it gives you string index keys, and on plain objects it also walks inherited enumerable properties.

## Generator functions (`function*`)
A generator is a function that can **pause and resume** execution, producing a sequence of values lazily via `yield`. It automatically implements `Symbol.iterator`.

```typescript
function* idGenerator(): Generator<number> {
    let id = 1;
    while (true) {
        yield id++;
    }
}

const gen = idGenerator();
console.log(gen.next().value); // 1
console.log(gen.next().value); // 2

for (const id of idGenerator()) {
    if (id > 3) break;
    console.log(id); // 1, 2, 3
}
```
Why this matters: generators let you model **infinite or lazily-computed sequences** (pagination cursors, ID generators, tree/graph traversal) without pre-computing an entire array in memory.

## Custom iterables (implementing the protocol manually)
```typescript
class Range implements Iterable<number> {
    constructor(private start: number, private end: number) {}

    *[Symbol.iterator](): Iterator<number> {
        for (let i = this.start; i < this.end; i++) {
            yield i;
        }
    }
}

for (const n of new Range(1, 4)) {
    console.log(n); // 1, 2, 3
}
```

## Async iterators & `for await...of`
For sequences produced asynchronously (e.g., paginated API results, streams):
```typescript
async function* fetchPages(url: string): AsyncGenerator<string[]> {
    let next: string | null = url;
    while (next) {
        const res = await fetch(next);
        const page = await res.json();
        yield page.items;
        next = page.nextUrl;
    }
}

async function consume() {
    for await (const items of fetchPages("/api/data")) {
        console.log(items);
    }
}
```

## Compiler note
Iterating with `for...of` over non-array iterables (`Map`, `Set`, generators) when targeting older JS (`ES5`) requires `"downlevelIteration": true` in `tsconfig.json`, otherwise the compiler falls back to index-based iteration that only works on arrays/strings.

## Interview quick hits
- **Q: What makes an object iterable?** Implementing `Symbol.iterator`, which returns an iterator with a `.next()` method.
- **Q: Key difference between `for...in` and `for...of`?** `for...in` gives keys/indices, `for...of` gives values.
- **Q: Why use generators over returning an array?** Laziness — values are computed on demand, supporting infinite sequences and lower memory usage.
- **Q: How do you consume an async generator?** `for await (const x of asyncGen())`.
