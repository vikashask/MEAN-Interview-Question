# TypeScript Namespaces

## What are namespaces?
Namespaces (originally called **"internal modules"**) are a TypeScript-only way to group related code under a single global name, avoiding naming collisions in the **global scope**. They predate ES modules.

```typescript
namespace Validation {
    export interface StringValidator {
        isAcceptable(s: string): boolean;
    }

    export class LettersOnlyValidator implements StringValidator {
        isAcceptable(s: string): boolean {
            return /^[A-Za-z]+$/.test(s);
        }
    }
}

// Usage
let validator = new Validation.LettersOnlyValidator();
```

Only members marked `export` are visible outside the namespace.

## Splitting a namespace across files
Use **triple-slash directives** to tell the compiler how files relate (order matters when compiling to a single output file):

```typescript
/// <reference path="Validation.ts" />
namespace Validation {
    export class ZipCodeValidator implements StringValidator { /* ... */ }
}
```

## Namespaces vs Modules — the decision that matters today
| | Namespace | ES Module |
|---|---|---|
| Scope | Global (single file/global object) | File-based, truly isolated |
| Bundler/tree-shaking friendly | No | Yes |
| Standard | TypeScript-only | JavaScript standard (ESM) |
| Recommended today | Avoid in app code | **Use this** |

> **Senior guidance:** In modern applications (Node.js, bundlers like Webpack/Vite, ESM/CommonJS), **prefer ES modules (`import`/`export`) over namespaces**. Namespaces are mostly seen today in:
> - Legacy codebases predating ES modules
> - **Ambient type declarations** (`.d.ts` files) for global libraries (e.g., typing a script-tag-loaded library like jQuery: `declare namespace $ { ... }`)
> - Grouping types/constants without runtime module overhead in non-bundled `<script>` scenarios

## Interview quick hits
- **Q: What problem did namespaces solve before ES modules existed?** Avoiding global scope pollution/name collisions.
- **Q: Should you use namespaces in a new Node.js/React app?** No — use ES modules; namespaces are now mainly relevant for typing legacy/global libraries.
- **Q: Can namespaces be merged across multiple files/declarations?** Yes — TypeScript merges same-named namespace declarations (declaration merging), one of the few things they still do well for ambient typings.

As we alluded in our note about terminology, “internal modules” are now referred to as “namespaces”.
